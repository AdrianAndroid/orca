# 第 4 章 · 删除管线与安全护栏

> 删除是这个子系统里护栏最密集的地方——几乎每条规则都能追溯到一个 bug 编号(#2259、#19334、#6433、#11163、#18275……)。
> 哲学一句话:**证据不足就不删,所有失败方向都偏向"不删"**。引用为仓库相对路径。

## 4.1 删除入口:请求合并与验收队列

### IPC handler(ipc/worktrees/removal/register-worktree-removal-handlers.ts:38-130)

流程:

1. `parseWorktreeId` 拆出 repoId/worktreePath;`resolveRepoForExecutionHost` 按 hostId 解析 repo。
2. `assertWslMoveRepoWritable`。
3. **先查后台 pending**:`waitForPendingWorktreeRemoval`(:47 注释:"Why: a retry or a second window asking while Git still deletes joins that removal.")——已有后台删除直接 join 其结果。
4. **内存 in-flight 合并**:key = `${hostId}\0${worktreeId}`,且 **optionsKey 必须相同**,否则抛 "Worktree deletion already in progress"。
5. 合并理由(:62):"Why: concurrent stale-toast/double-click/sidebar races can hit the same worktree; share the op so only one path touches Git and disk."
6. `catalogVersion` 在共享 promise 内打戳(:114-116):"a coalesced second caller gets the same reply, naming the catalog this removal produced."
7. finally 中仅当 map 里仍是同一个 promise 才删除——避免晚到的替换者被误清。

### optionsKey 的构成(worktree-removal-coordinator.ts:10-35)

```
${forceKey}:${archiveKey}:${ptyKey}:${archiveFailureKey}${checkoutKey}
```

- `force`: 'force' / 'normal'
- `skipArchive`: 'skip-archive' / 'run-archive'
- `allowUnverifiedPtyStop`(:23-24):"Why: a Force Delete retry must not coalesce onto the in-flight attempt that just failed the PTY gate — **it would inherit that failure instead of retrying**."
- `allowFailedArchiveHook`(:26-27):"Same reason for the archive waiver: a retry that waives the failed hook must not coalesce onto the in-flight attempt that is about to refuse on it."

**设计要点**:选项不同的重试绝不合并到在途请求——合并是去重,但继承别人的失败就不是重试了。

### per-repo 验收串行队列(worktree-removal-acceptance-queue.ts,全文 15 行)

docstring(:5-9):

> "Runs one local removal's archive hook, preflight and teardown only after the previous removal in the same repo was accepted, whichever client asked: **hooks that write refs race the repo's ref locks (#2259)**. Git's checkout delete runs after acceptance, in parallel under its own limit."

——验收阶段(archive hook、preflight、teardown 准备)按 repo 串行;真正的 checkout 删除在验收之后、在自己的并发限制下并行。accept 闭包内等待期间再次 `waitForPendingWorktreeRemoval`("another client's removal of this worktree may have been accepted during the wait")。

### Archive hook 是硬性前置(#19334)

execute-worktree-removal.ts:155-156:

> "**Precondition, not an advisory (#19334)**: both branches below stop PTYs and delete the checkout, so a hook failure has to throw here — before either is reached."

gate 的 docstring(worktree-archive-hook-gate.ts:9-15):"Call it while the checkout, its registration, its agents and its ownership evidence are all still intact: on a failure it throws, and no caller may stop a PTY, deregister, or delete before it has returned."

失败未豁免 → 抛 `WorktreeArchiveHookFailedError`;`allowFailedArchiveHook` → 记 `archiveHookOverride` 放行。

**stale-registration 快路径排在 archive hook 之前**,顺序是刻意的(:106-109):

> "both arms describe a registration with no checkout behind it — a row whose path IS a `.git` file, or a tree already gone from disk. There is nothing to archive, and running the hook would fail on the missing cwd and block a cleanup that has no user data to lose."

## 4.2 `executeWorktreeRemoval` 阶段顺序(ipc/worktrees/removal/execute-worktree-removal.ts)

```
 1. Folder repo 分流(:47-49)→ removeFolderWorkspace
 2. 路由检查(:50-53):connectionId → 抛 SshHostNotServedError
 3. 严格列表(:54-58)listGitWorktreesStrict —— 列表失败直接抛,绝不用宽松列表
 4. 取元数据 resolveWorktreeRemovalMetadata
 5. 注册判定 findRegisteredDeletableWorktree(安全栈,§4.6)
 6. 嵌套删除批准校验 assertNestedWorktreeRemovalApproval
 7. 失败删除重试路径(:72-81)retryFailedRemovalUnlessRegistered
 8. 未注册/孤儿路径(:82-95)removeUnregisteredWorktree
 9. canonicalWorktreePath 以 Git 注册为准;deleteBranch = !preserveBranchOnDelete
10. 锁校验 assertWorktreeUnlockedForRemoval
11. stale-registration 快路径(:110-149)
12. archive hook(§4.1)
13. removeRegisteredLocalWorktree(§4.3)
```

### 失败删除重试路径(worktree-removal-leftover.ts:84-101)

- Git 重新注册了该路径 → 丢弃 failed 记录,走正常路径("a checkout Git registers at the path again is the normal delete's, so the failed record is dropped")
- 有 failed 记录且目录残留 → 拒绝(先查嵌套注册 worktree:"removing the folder, as the refusal asks, would delete that worktree's files too")
- 否则重放记录的后台 job(见 §4.4)

### stale-registration 快路径

条件:注册的 path 本身是 `.git` 文件且 prunable(worktree-prunable-git-file.ts:7-41:prunable、非 main、非 bare、未锁、有分支、有 head、basename 为 `.git`、stat 证实是 file),或 Windows force + 已从磁盘消失 + 有 meta。动作 = `git worktree prune` + 验证 Git 忘了这行 + 全套元数据清理。

### 未注册/孤儿路径(remove-unregistered-worktree.ts)

- **孤儿目录清理**(:51-106)需三重证据全部通过:Orca provenance meta + 非危险路径 + 孤儿目录安全证明(§4.6)。非 force 抛 `ORPHANED_WORKTREE_DIRECTORY_MESSAGE`;force:watcher gate → 停 PTY → 递归删 → 清理。
- **已消失路径**(:107-136):无 meta 且非 force → 抛错(:109:"Why: without persisted metadata, require the renderer recovery path before deleting Orca-only state for an unregistered path.");有 meta 无需 force(:112:"a manually deleted worktree is already gone; persisted metadata proves it was an Orca-known row")。
- **兜底**(:137):"Refusing to delete unregistered worktree path"——未经 Git 注册且无 Orca provenance 的路径**绝不删**。

## 4.3 `removeRegisteredLocalWorktree`(remove-registered-local-worktree.ts)

按顺序:

1. **重校验**(:62-75):重新 `listGitWorktreesStrict` + `findRegisteredDeletableWorktree`——找不到抛 "Worktree registration changed during deletion: ... Retry deletion."(**删除中途注册可能变化**)
2. **锁复查**(:79-84):"Why: an archive hook can race another Git client that locks the row; recheck before linked-path/watcher/terminal teardown."
3. **symlink 链接路径**(:86-92):"Why: `orca.yaml` shared directories are symlinked in too, and a directory-only ignore rule leaves those links untracked, so removal must tolerate and unlink them exactly like the per-user shared paths."
4. **clean-tree preflight**(:93-109):`assertWorktreeCleanForRemoval`(带 ignoredUntrackedPaths);orphan 兼容错误放行但保持严格 PTY teardown(:108:"Git can still classify this as an orphan after preflight; keep strict PTY teardown before any recursive fallback deletion.")
5. **watcher gate**(:111-113):`runtime.acquireFileWatcherRemoval(canonicalWorktreePath)`
6. **PTY 停止**(:114-133):"Why: hold the watcher/terminal gate through Git and any recursive fallback so no late spawn recreates a native handle. Linked-path deletion is destructive too, so PTYs must release every handle before Windows or WSL filesystem cleanup starts."
7. **unlink symlink**(:124-127):"preflight only ignored these paths, not mutated them; keep watcher installs fenced through Git removal."
8. **inline vs background**(:160-188):非 WSL → 后台,立即返回 `{removing: true}`。注释(:165-166):

   > "Why detached: every refusal above already ran, and Git's 20-35 s delete must finish even when the request that asked for it goes away; other views read the host's `removing` marker meanwhile."

9. **finishLocalWorktreeRemoval**(:191-321):
   - `removeWorktree(...)` 带 `knownRemovedWorktree`(:229:"reuse the authoritative worktree list already computed here instead of rescanning siblings on the hot delete path")
   - 失败三分支:Windows 部分删除恢复(§4.8)/ orphan 错误 → `cleanupLocalOrphanedWorktreeDirectory` + `git worktree prune`(:266:"remove failed so git still tracks it (.git/worktrees/<name>); prune or the stale entry keeps its branch locked.")/ 其他 → 格式化抛出
   - 成功后(:294-295):"the worktree is unlisted from here on; a scan that began before the removal is overtaken" → `runWorktreeChangeInvalidators`

## 4.4 git 层删除(git/worktree-removal.ts)

### removeWorktree 包装(:26-47)

```ts
// Removal deletes branches, and a ref deletion needs the packed-refs lock a running idle
// pack holds while it rewrites. Waits that window out; the prune phase that follows it
// is concurrency-safe and is left to finish.
withRepoRefMaintenancePaused('worktree-remove', ...)
```

`options.forceBranchDelete`(:30):"for failed-creation rollback (fresh branch, no user work); user deletes leave it false so unmerged commits survive."

### performRemoveWorktree(:49-95)

- **无超时是设计决定**(:66-67):"Why no timeout: this is a write, so none applies by default, and Git deletes the whole checkout here (**prod p90 29 s**); a deadline would kill a legitimate large delete halfway through."
- **长路径**(:68-69):"creation checks out with them on Windows, so deleting without them fails with 'Filename too long' (#6433) and leaves the branch behind via the Windows recovery."
- 命令:`git [longPathArgs] worktree remove [--force] <path>`,带 `signal: checkoutDeleteSignal`、`removalGitEnv()`、`admissionExempt: true`

### 分支删除:per-repo 串行 + merged-only(:97-112)

> "Why its own span: branch cleanup can reach the network (`fetch --prune`), so a stall here reads as `git worktree remove` being slow unless it is timed separately.
> Why serialized per repo: concurrent removals in one repo race `packed-refs.lock` and the remote-tracking ref locks of `fetch --prune` (#2259); the checkout deletes above need not wait."

git/worktree-branch-removal.ts 的规则:

- 默认 `git branch -d`(非 `-D`):"`-d` (not `-D`) preserves unmerged work, and forceBranchDelete opts into `-D` for failed-creation rollback."
- "checked out in another worktree" 失败 → 先 `git worktree prune` 再重试(:86:"only pay for `worktree prune` when a stale admin record may be blocking `branch -d`")
- `-d` 失败兜底:**squash merge 场景**(:124:"squash merges rewrite commit IDs, so `branch -d` rejects already-merged branches; delete only when Git proves no unmerged tree changes.")——用 quarantine 证明无未合并改动后才强删
- 仍失败 → **保留分支**返回 `{preservedBranch}`(:57:"Keep an unmerged/unpublished branch: deleting a worktree must never silently discard commits.")
- 强删用条件更新(:164):"Why: stale toast actions must not delete a branch that moved; `update-ref -d` deletes only if the ref still == expectedHead."

### GIT_ASK_YESNO 清洗(:172-183)

> "Why: Git for Windows runs $GIT_ASK_YESNO when a file stays locked mid-delete; no prompt program may run here."

### Windows junction 残留(:185-205)

> "Why: Git for Windows does not descend into junctions and exits 0 with them and their parent directories still on disk; finish the delete Git already accepted instead of leaving it behind."

WSL 路径跳过(:191:"WSL-owned checkouts are deleted inside the distro, so Node on Windows must not touch them.")。

### finishUnregisteredWorktreeRemoval(:114-117)

> "Finishes a removal whose checkout Git no longer registers and is gone from disk: stale admin records, then the branch. **Deletes no files: Orca removes a checkout only through Git.** `assertCheckoutGone` refuses while anything is still at the path."

## 4.5 后台删除与删除记录(WAL 协议)

### record-before-delete(worktree-background-removal.ts:293-314)

> "Why: the record should be on disk before Git deletes, so a quit resumes the delete, but a disk or file pool stall must not hold the user's delete; past this, a crash only loses the resume."

`RECORD_WRITE_WAIT_MS = 2_000`:等持久化最多 2 秒,超时仅 warn 照样删。**记录先于删除落盘是目标,但磁盘卡顿不能劫持用户的删除**——超时的代价只是崩溃后丢失"续删"能力。

### detached job 与 quit 行为

- 每 job 一个 AbortController;orderly quit 时 `stopBackgroundWorkremovals`(:209-213)abort 全部:"stops each checkout delete Git is running, without waiting for it to exit." stopSignal 只传给 checkout delete。
- `settleBackgroundWorktreeRemoval`(:237-291):
  - **abort** → 直接 return,记录留在表内(:256-257:"quit stopped Git; the record stays so the next start finishes this delete.")
  - **成功** → WeakSet 记 finished、resolve settlement
  - **失败** → 记入 `failedWorktreeRemovals`(:261-262:"Git drops the registration even when it fails to delete the checkout, and Orca lists workspaces from Git, so without the record the leftover would vanish with no way to retry.")
  - 失败也清 pending(:268-269:"the row returns with its error and Delete retries it; **nothing retries unseen**.")
  - publish 先于落盘(:285-286:"a crash before it lands only re-runs a finish that re-derives what is left from Git")

### failed 记录的重放保护(:184-190)

> "Why: the recorded choices (force, branch) were for the leftover; a checkout Git registered at the path after the caller listed is a new one, which only the normal delete may remove."

重放前 `isCheckoutRegistered(record)` 为真 → 抛 "A different checkout is now at ...; Orca left it in place."

### 删除记录文件(worktree-removal-records.ts)

- `orca-worktree-removals.json`,存 profile storage 目录。头注释(:1-3):

  > "Why a sidecar beside the profile state: the record must be on disk before Git starts deleting, and profile-state writes are batched; the sidecar writer fsyncs and renames atomically. It also keeps a host-local, in-flight obligation out of profile exports and backups."

- 记录字段:worktreeId、repoId、repoPath、worktreePath、branch、head、deleteBranch、force、requestedAt,可选 `failure`。
- 解析宽容:"a missing or unreadable file reads as none."
- sidecar 写入(sidecar-snapshot-file.ts):临时文件 + fsync + 原子 rename;按文件串行 read-modify-write("patch/prune cycles cannot interleave")。

### 三态表(worktree-removal-table.ts)

- `pendingWorktreeRemovals`:"mirrored to disk on every change; listings and joins read only this."
- `failedWorktreeRemovals`:"listed with their error until the checkout disappears or is replaced... **Never retried unasked.**"
- `finishedWorktreeRemovals` = WeakSet:"a listing that read Git before a delete finished holds the record until it replies."
- `worktreeCheckoutExists`:"**Unreadable counts as present**: only a checkout proven gone ends a failed delete."

### 启动恢复

`loadWorktreeRemovalRecords`(:46-77)+ `resumeInterruptedWorktreeRemovals`(:197-206):pending 记录重跑同一删除;加载时拿 watcher fence——"session restore cannot open a terminal or watcher in a half-deleted checkout before the resume"(:43-44);resumed job 接管自己 gate 的同 tick 移交 fence(`releaseStartupRemovalFence`:"call in the same tick the job takes its own gate")。

## 4.6 安全栈(worktree-removal-safety.ts)

### `isDangerousWorktreeRemovalPath`(:54-81)全部检查

1. 空/空白路径 → dangerous
2. worktree == repo 本体 → dangerous
3. 解析后 == 文件系统根 → dangerous
4. worktree **包含** repo 目录 → dangerous
5. home 守卫(§4.7)——注释(:79):"Raw, not `resolvedWorktreePath`: the guard re-reads the path under its own syntax too."

`containsPath` 的边界(:68):"Why: `..name` is a valid child name; only `..` and `../...` escape."

### `findRegisteredDeletableWorktree`(:96-115)

列表中找不到 → null(上层抛 "Refusing to delete unregistered worktree path");找到但 home authority 未解析 / 是 main worktree / 危险路径 → 抛 "Refusing to delete protected worktree path";然后嵌套守卫。

### 嵌套 worktree 守卫(:117-133)

> "Why: `git worktree remove --force` treats nested worktrees as ordinary untracked directories and deletes their working files while leaving Git with a prunable child worktree record."

### 孤儿证明:为什么必须是 `.git` **文件**(:135-164)

> "Why: this answer authorises a recursive delete, and the proof it relies on — a `.git` file at the top of the directory — is also what a bare-repo dotfiles home looks like. An execution host that never named its home leaves that check with nothing to compare against, and `unverifiable` does not authorise a delete."

`worktree-orphan-gitdir-proof.ts` 的完整证明链:

1. `<path>/.git` 必须是**文件**(linked worktree 标志;普通克隆/dotfiles bare repo 是 `.git` **目录**,绝不满足)
2. 解析 `gitdir: <path>` 首行
3. gitdir 必须直接位于 repo 的 worktrees 管理目录下一层
4. repo 本身若是 linked worktree,需 admin backlink 证明(:125-127:"a separate git dir can live under a directory named `worktrees`; only the admin backlink proves the repo path is itself a linked worktree")
5. admin entry 的 `gitdir` 文件必须**回指** `<candidate>/.git`(:177-179:"copied .git files can target another worktree's admin entry; only Git's back-reference proves that entry still belongs to this candidate")
6. **全程任何异常 → false**(失败方向保守)

### Orca provenance(:166-203)

- `ORCA_CREATION_SOURCES = {'desktop','runtime','cli','ssh'}`
- 当前证据:`orcaCreatedAt` 为 number 且 source 在集合内;legacy 证据:`createdAt | createdWithAgent | pushTarget | ...` 任一存在
- (:177-179):"Why: **path shape alone is not authority**; users can create plain Git worktrees inside Orca's workspace directory too."
- `stripOrcaProvenanceMetaUpdates`(:205-213):从 meta 更新中剥掉全部 provenance key——**用户/导入无法伪造"这是 Orca 建的"**(伪造 = 骗系统删除它无权删的目录)

## 4.7 Home 守卫(worktree-removal-home-guard.ts)

### 类型(:24-38)

```ts
type WorktreeRemovalHomeAuthority =
  | { kind: 'client' }                                    // 本机,os.homedir() 权威
  | { kind: 'executionHost'; homePath: string | null }    // 远端,用其上报的 home
```

`executionHostRemovalHome` 用 `homePath || null`(:36:"an empty answer is an absent one, and `''` would otherwise read as a resolved home")。

文件头动机(:1-15):客户端 `os.homedir()` 对 SSH host 既不必要也不充分——"a Windows host profile (`C:\Users\bob`) went unrecognised from a macOS desktop and a coincidental client-home prefix could refuse a legitimate remote delete (#18275)"。所以**一切由路径语法决定,语法是可携带的**:"a Windows profile is a Windows profile no matter which desktop is looking at it."

### unverifiable 永不授权(:40-59,全章最重要的一段注释)

> "`false` is `unverifiable`, not "no home here". Every gate in `worktree-removal-safety.ts` that authorises a delete requires `true`, because nothing else in reach rules out a home directory:
> - The orphan gates accept a `.git` file at the top of a directory as proof, **which is also what a bare-repo dotfiles `$HOME` looks like**.
> - The registry does not help either. `git worktree add` takes a pre-existing empty directory, and that directory can afterwards be somebody's `$HOME` — a build account's home, a container's `HOME=/workspace`. Being a linked worktree of the repo proves provenance, **not that the path is not a home**, and `git worktree remove --force` deletes the checkout.
> With the host's answer both are caught by containment. Without it only the path shapes remain, and a home at a non-standard location has no shape to match."

**推理链**:两条授权删除的路径(`.git` 文件孤儿证明、Git 注册)都无法排除"这个目录是某人的 $HOME"→ 所以 host 未报告 home 时,永不授权递归删除。

### 路径语法检测覆盖(:86-216)

- **dual pathOps reading**(:94-98):"a Windows-shaped repo path drags a POSIX worktree path into win32 rules and `/home/alice` stops matching anything. Read the path in its own syntax as well, and refuse if either reading names a home."
- `getPathOps`(:61-64):"forward-slash UNC roots need win32 ops; POSIX joins collapse `//Server` to `/Server`."
- home 只回答同语法路径(:118-125):"Comparing `C:\Users\bob` against a POSIX client home is meaningless in both directions."
- POSIX 形状:`/home`、`/root`、`/Users`、`/home/<x>`、`/Users/<x>`
- Windows:`<任意卷>\Users[\<name>]`,含 UNC `\\server\share\Users\bob`
- WSL:`\\wsl.localhost\Ubuntu\home\alice` 走 POSIX 形状;`/mnt/<letter>` 是 drvfs 视图,`\\wsl.localhost\Ubuntu\mnt\c\Users\bob` 换算成 `C:\Users\bob` 走 Windows 规则(:193-194:"`/mnt/c` is the whole volume… its drvfs spelling has to be refused here, since its win32 root is the distro share")
- `equalsWindowsPath`(:212-215):"Windows drive and UNC roots fold case, so `c:\users\bob` is the same profile."

## 4.8 删除路由与 Windows 恢复

### 删除的执行主机路由(worktree-removal-execution-host-route.ts)

头注释(:1-28)讲 #11163 的删除侧版本:旧代码元数据用解析的 host、文件系统步骤读裸 `connectionId`,结果"deleted a same-named local directory while metadata was pruned under `ssh:<target>`"。现在 "Routing is now one answer for the whole removal"。

- `local` → 服务;`runtime` / `ssh` → 抛错("**Loss of contact is never evidence that the checkout is local**")
- **咨询谁的 home**(:77-91):`local` → `CLIENT_REMOVAL_HOME`;其他 → `executionHostRemovalHome(null)` = unverifiable。注释(:73-76):

  > "Keyed on the resolved `ExecutionHostId`, not on `repo.connectionId`: a row naming its owner only as `executionHostId: 'ssh:<target>'` has a null `connectionId`, and answering that with this client's home is how the guard would vouch for the wrong machine (#11163)."

  以及(:84-85):"Why spelled out rather than a `default`: no other host's home is known here, and this client's home vouches for nothing on it — **a host kind added later has to come here and say**."(新增主机类型必须显式表态,default 分支不存在。)

### Windows 部分删除恢复(local-worktree-removal-recovery.ts:111-152)

条件链:

1. 先 `assertWorktreeUnlockedForRemoval`(:114-115:"recovery can recursively delete the remaining directory, so a Git lock must reject the attempt before classification or any side effects")
2. `process.platform === 'win32'` + **重新 `listWorktreesStrict` 证明 Git 已不再注册该路径**(:144-145:"error prose can be localized or ambiguous. **Only a missing Git row proves removal started** and makes recursive Windows cleanup safe.")
3. 恢复动作:先 `closeWatcher`("must fail closed while a watcher process may still own a native handle")→ 递归删 → `git worktree prune` + 验证(:92-93:"Git prune exits successfully while retaining locked registrations")→ 保留分支(:106-107:"if Git detached the row before reporting its filesystem error, keep the branch rather than guessing whether the normal branch cleanup ran")

## 4.9 本章设计要点回顾

1. **合并≠去重**:optionsKey 保证重试不继承在途失败(§4.1)。
2. **hook 是前置条件不是建议**(#19334),且在一切副作用(停 PTY、删检出)之前求值(§4.1)。
3. **WAL 协议**:记录先于 Git 删除落盘,但有 2s 预算——持久化不能劫持用户操作(§4.5)。
4. **每步重校验**:删除中途重新列表、锁复查、回指证明——世界在变,证据要新鲜(§4.3/4.6)。
5. **空是未知不是安全**:unreadable = present;空 home = unverifiable;错误文案不可信,只有 Git 行消失才算证据(§4.5/4.7/4.8)。
6. **分支删除保守到底**:merged-only、squash 场景要证明、强删用条件 `update-ref`、删不掉就保留——"deleting a worktree must never silently discard commits"(§4.4)。

# 第 6 章 · 设计模式、原则与阅读路径

> 前五章讲"是什么",本章讲"为什么是这样"——把散布在 60+ 文件里的决策提炼成可迁移的模式,并给出按投入产出比排序的阅读路径。

## 6.1 并发设计模式汇总

这个子系统是并发设计模式的宝库。每种模式都附出处,可直接跳去读实现。

| # | 模式 | 体现 | 出处 |
|---|---|---|---|
| 1 | **同步性代替锁** | select 和 take 放同一同步回合,靠 JS 单线程语义消除竞态,零锁 | `worktree-create-preparation-claim.ts:79-82` |
| 2 | **await 后重读世界** | 每次 await 都是并发窗口;reservePreparation 三次重选池子,候选变了宁可 miss | `worktree-create-preparation-reservation.ts:46-87` |
| 3 | **愿望+断言双查** | 命名阶段查 pending 删除冲突(愿望),git 层 `assertNoPendingWorktreeRemovalConflict` 再查(断言) | `worktree-remote.ts:1298` + `git/worktree-add.ts:238` |
| 4 | **合并带 options key** | 相同目标不同选项不合并——Force Delete 重试不继承在途失败 | `worktree-removal-coordinator.ts:10-35` |
| 5 | **按 repo 串行化** | 删除验收段、分支删除按 repo 串行,防 `packed-refs.lock` 竞争(#2259) | `worktree-removal-acceptance-queue.ts` |
| 6 | **WAL:记录先于操作落盘** | 删除记录先 fsync 落盘(2s 预算),崩溃后按记录续删 | `worktree-background-removal.ts:293-314` |
| 7 | **世代号防伪** | epoch UUID + per-repo 单调世代;过期扫描永不发布 | `local-worktree-scan-generation.ts` |
| 8 | **读不推进失效** | mutationRevision 与 generationSequence 分离——读路径永不使有效快照失效 | `local-worktree-scan-generation.ts:45-58` |
| 9 | **ABA 防护** | instanceId 每次创建轮换;父节点证实消失再轮换 | `worktree-remote.ts:1526`、`worktree-lineage-pruning.ts:132` |
| 10 | **优先级准入** | ALS 传播 tier;interactive 压过 status 的投机工作;15s 老化防饿死 | `git-operation-executor.ts`、`git-admission-scheduler.ts` |
| 11 | **独占文件写当锁** | `wx` 写 `locked` 文件验证所有权;丢锁 = 放弃一切清理权利 | `git/worktree-preparation-lock.ts:71-87` |
| 12 | **证据新鲜化** | 删除中途重新列表、锁复查、gitdir 回指证明——证据会过期,破坏性步骤前要重取 | `remove-registered-local-worktree.ts:62-84` |
| 13 | **条件更新防误伤** | 强删分支用 `update-ref -d <ref> <expectedHead>`——ref 动了就删不掉 | `git/worktree-branch-removal.ts:164` |
| 14 | **defer 到外层 finally** | re-arm thunk 由创建最外层 finally 触发,不与创建抢准入槽,失败也补货 | `worktree-remote.ts:966-976` |
| 15 | **证据门控的维护任务** | 元数据剪枝由事件驱动而非时钟,且只认"更可删"方向的信号 | `local-worktree-metadata-prune-gate.ts` |

## 6.2 五条贯穿性原则

### 原则一:Fail-closed 的破坏语义

每个护栏的失败方向都偏向"不动作":

- unverifiable home → 不授权删
- 一次空列表 → 不证明批量消失
- unreadable checkout → 算作存在
- 锁丢失 → 不是我们的,谁都不删
- provenance 缺失 → 拒绝递归清理
- `unknown` 分歧探测 → 走冷创建

### 原则二:单点解析,禁止回退

主机身份只在一个地方解析;遇到远程主机一律抛错,绝不"帮你在本地试试"。新增主机类型必须显式表态("a host kind added later has to come here and say")。一整类 bug(#11163)从结构上被消灭。

### 原则三:空是危险值,不是安全值

空列表、空 home、空回答全部被当作"未知"而非"没有":

- `executionHostRemovalHome` 里 `homePath || null`:"an empty answer is an absent one"
- 列表失败抛错而非 `[]`
- "unverifiable, not 'no home here'"

### 原则四:投机有预算

预备池的每一项投机开销都有上限——数量(3)、时间(5min TTL)、分歧(100 commits + 共同祖先 + 端到端 deadline)、频率(burst 门控)、优先级(status tier)。猜测错了的代价被严格封顶;任何不确定都退化到冷路径。

### 原则五:"Why" 注释即制度

几乎每个护栏都有引用 bug 编号或推理过程的注释(#2259、#11163、#17775、#19334、#18275、#6433、#9944……)。这不是文档习惯,而是把"**为什么不能简化**"固化在代码里,防止后来者在不知情中拆掉护栏。本系列 wiki 的大量内容其实就是这些注释的编目。

## 6.3 反模式对照(这里刻意不做的)

| 不做 | 因为 |
|---|---|
| 用 `repo.connectionId` 判断主机 | #11163:只有 `executionHostId` 的行会被误判为本地 |
| 列表失败返回 `[]` | 空列表会被当权威,剪除活元数据(#1158 等) |
| 给删除加超时 | p90 删除 29s,超时会把合法大删除杀在半截 |
| kill 正在运行的 git pack | 会留下 `refs/**` 锁,约 1/5 概率;等它的 0.03-1.37s 窗口即可 |
| 按时钟跑元数据剪枝 | #17775:100:1 悬空行风暴曾卡死主进程 |
| 路径形状推断所有权 | 用户可在 workspace 目录里自建 git worktree;dotfiles `$HOME` 也有 `.git` |
| 合并不同选项的删除请求 | 重试会继承在途失败(PT gate / archive 拒绝) |
| 删除时 `branch -D` | "deleting a worktree must never silently discard commits" |
| checkout 物化预备检出 | 会触发用户 post-checkout 钩子;用 `reset --hard` 代替 |
| 遥测里带分支名/路径 | 阶段名/miss reason 是封闭词汇,防止用户内容进 span |

## 6.4 推荐阅读路径

按这个顺序读源码,投入产出比最高(每章开头的模块全景表也可当地图用)。

**第一遍:建立骨架(~1.5h)**
1. `src/main/worktree-create-preparation-claim.ts`(131 行,全文)——整个文件就是一节并发设计课
2. `src/main/worktree-create-preparation-pool.ts:45-160`——池子边界与条目结构
3. `src/main/worktree-removal-safety.ts:54-140`——护栏堆叠
4. `src/main/worktree-removal-home-guard.ts:40-99`——unverifiable 论证,全系统最重要的一段注释
5. 本 wiki 第 1 章的 §1.7 对照图

**第二遍:深入机制(~3h)**
6. `src/main/ipc/worktree-remote.ts:957-1480`——创建编排(对照第 2 章 §2.1 阶段表)
7. `src/main/worktree-create-preparation-reservation.ts:32-96`——await 后重读
8. `src/main/git/worktree-create-preparation.ts`——prepare + finalize(对照第 3 章 §3.2/3.6)
9. `src/main/git/worktree-preparation-lock.ts`——锁机制(71-88 是核心)
10. `src/main/ipc/worktrees/removal/execute-worktree-removal.ts`——删除编排
11. `src/main/worktree-background-removal.ts:139-314`——WAL 与崩溃恢复

**第三遍:边界与兼容(~2h)**
12. `src/main/worktree-create-execution-host-route.ts` + `worktree-removal-execution-host-route.ts`——两个头注释都要读
13. `src/main/worktree-name-retirement.ts:183-307` + `worktree-retirement-namespace.ts`——退休注册表
14. `src/main/local-worktree-scan-generation.ts` + `local-worktree-metadata-prune-gate.ts`——世代号与门控(两个文件都不长,头注释是精华)
15. `src/main/git/worktree-list-reader.ts:60-110, 220-255`——Git 版本回退
16. `src/main/git/worktree-branch-removal.ts`——分支删除的保守主义

**配合阅读**:每个核心文件旁边都有同名 `.test.ts`。护栏类文件的测试是学习"攻击面"的最好材料——**测试名即威胁模型**。

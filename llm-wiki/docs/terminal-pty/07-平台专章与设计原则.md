## 7.1 Windows:三道独立的保命工程

### ① daemon-host relocation:逃出安装目录

问题(`src/main/daemon/daemon-host-relocation.ts:31-41`):

> "the NSIS installer deletes the old install and **force-kills every process imaged under it**, which would otherwise kill the daemon and its live terminals."

自动更新 = 旧安装目录下所有进程镜像被强杀。daemon 必须从安装目录搬走:

- **搬到哪**:`%LOCALAPPDATA%/Orca/daemon-host-profiles/<profileHash>/<version>/build-<nonce>/`——**LOCAL 而非 roaming**,防 OneDrive 同步这 ~260MB 运行时(:80-81,与 NSIS 卸载脚本共享约定);
- **搬什么**:run-as-node 的 Orca.exe 副本(不是 node.exe——无 console 闪烁、asar 仍可解析)+ daemon-entry.js + windows-process-tree;
- **逃逸的是路径不是文件名**(:38-40):"electron-builder's kill sweep selects processes whose image path sits under `$INSTDIR`, which is why the exe is **copied verbatim rather than renamed**"——改名毫无用处,杀是按路径选的;
- **原子发布**:staging 目录 → marker 校验 → 单次 `renameSync`(:274-281);"a same-version daemon may still load files from an older mirror"——旧镜像继续服役;
- **fail-open**:任何失败返回 null,回退到安装目录 fork(搬迁前的行为,:36);
- **prune 保守**:只回收"非当前版本且无活 daemon pid 记录钉住"的目录(`collectPinnedDaemonVersions:300-348`,含空 pid 记录的 quarantine 处理)——回收条件又是"正面证据"风格;
- **路径深度预算**:`daemonHostFitsPathBudget`(:268-273)——太深 conpty.dll 加载失败。

### ② job object 与 breakaway(第 3 章已详)

要点回顾:CREATE_SUSPENDED 先入 job 再跑;MSYS/Cygwin 严格成员制;刻意不加 KILL_ON_JOB_CLOSE;宿主 kill-on-close job 兜底 daemon 崩溃。**AGENTS.md 的警告**:不含 breakaway 修复的旧构建 `conpty.node` 能通过所有现存门检——改动必须重建实测。

### ③ taskkill 也要防卡死

`src/main/windows-process-tree-kill.ts`:`taskkill /pid /T /F` + **5 秒超时**(:8,"Bound hung taskkill so killRoot still runs";:38 "#10004 review"),`windowsHide: true`,且经 `admitSelfInitiatedTreeKill` 防误杀自家 Chromium 树。**连杀进程的工具本身都不可信**——这是 Windows 子系统的基本情绪。

### ④ SSH 远端的 breakaway 契约

SSH 会话本身在一个 job 里,远端启动的 daemon 会被会话结束带走。解法:`src/shared/windows-breakaway-launch.ts:1-12`——`--windows-breakaway-launch` 一次性 launcher 模式,`CREATE_BREAKAWAY_FROM_JOB` 逃出 SSH session 的 job;exit codes:launched/failed/unavailable;WMI 兜底。relay.js 与 orcad.js 都暴露这个模式,flag 共享、各自命名参数分隔符。

## 7.2 macOS:TCC 归因——权限记到"路径"头上

完整文档:`docs/reference/macos-daemon-tcc-attribution.md`(issue #13921,签名证据 PR #25848)。问题:

> "A daemon forked from the app runs as `Orca Helper` and macOS charges its privacy access **to the app at its original path**. While an update replaces that path, a daemon that first touches a protected file is denied, and **the denial persists after the new bundle arrives even though System Settings still shows the grant**."

TCC(隐私授权)按路径记账。更新替换路径后,活着的 daemon 首次访问受保护文件即被拒——且设置界面看起来授权还在。更微妙的是:**仅可执行文件缺失不会触发**——已经读过受保护文件的 daemon 在旧二进制被删后继续工作。所以症状是间歇的、与首次访问时机相关的。

### 解法:launchd + 签名副本

- **签名 helper**:每个打包 app 带 `Contents/Helpers/Orca Terminal Host.app`(~124 MiB:pinned Node + daemon JS + node-pty);`config/scripts/macos-terminal-host-bundle.cjs` 在 afterPack 构建签名,并做一次真实 PTY round-trip 验证,任何 layout/Info.plist/OS floor/架构/签名漂移都 fail 构建;
- **按 CDHash 存副本**:`userData/daemon-host/macos/terminal-host-<cdhash>/app.noindex/…`;APFS clone(否则普通拷贝)→ `codesign --verify --strict` → 单次 rename 发布——**输给另一个发布者也没关系**(幂等);
- **launchd 启动**(`macos-daemon-launchd.ts`):非持久 job,label 含 profile hash 与协议版本;`AssociatedBundleIdentifiers=com.stablyai.orca` 让 Local Network 授权归属 app;job 文件 0600 用后即删;
- **helper 复用 app 标识符**的原因:继承全部既有 TCC 授权,含 Full Disk Access;
- **fallback 矩阵**:`launchMacDaemonFromStableBundle` 返回 null 才 fork,fallback reason 打日志(prepare-failed/deadline/bootstrap-refused/exited-before-ready/endpoint-taken);`MAC_STABLE_LAUNCH_HANDOFF_MS` 保证 fork readiness 仍装进 60s 门(第 1 章 §1.4 ③);仅 Developer ID 构建真正走 helper——adhoc 签名的 designated requirement 是 cdhash,helper 匹配不上,只能 fork;
- **清理**:后台收集旧副本,`lsof +D` 只有空 stdout 才算 unused;
- **登录会话死亡监视**:`macos-login-session-death-watch.ts`——GUI daemon 随登录会话走;headless/SSH daemon 必须活下来(第 2 章 §2.1)。

### 运行时健康监测

- TCC 归因健康:`daemon-tcc-attribution.ts:38`——"If that binary path disappears while the daemon survives, tccd…"(副本路径消失 = 授权归属断裂的前兆);
- system resolver 健康:`network/macos-system-resolver-health.ts`;
- 两者都是第 2 章 §2.4"健康驱动替换"的输入。

## 7.3 设计原则汇总

| # | 原则 | 体现 |
|---|---|---|
| 1 | **终端是用户的财产** | 断连不杀;job 刻意不带 KILL_ON_JOB_CLOSE;正常退出留下什么用户说了算 |
| 2 | **"说不清"保持"说不清"** | 端点协议 "Never collapse 'can't tell' into 'dead'";prune 要 pid 正面证据;liveness 三态 |
| 3 | **原子发布 + 内容寻址** | socket rename、wrapper hash 目录、history checkpoint staging、macOS 副本 rename——全系统没有"写到一半可见"的状态 |
| 4 | **撕裂与洞都要可检测** | OCKL 帧长度前缀、seq 连续性、UTF-8/UTF-16 截断对齐;"corrupt 比 stale 更糟" |
| 5 | **失败方向 = 保留** | fail-open 到本地 PTY;回退未包装 shell;prune 只删证据确凿的;quarantine 而非删除 |
| 6 | **成本预付与门控** | ConPTY 预热 2.7s→70ms;dirty-gate checkpoint;5MB 触发重置;256 进程上限 |
| 7 | **版本化的长期共存** | PROTOCOL_VERSION=48;多代 daemon 路由;seed 移交 v30 门槛;老 build 认得新目录 |
| 8 | **测试即威胁模型** | repro-12101/13767/7329 事故回归;`windows-pty-job.win32.test.ts:150-190` 诚实标注"未覆盖 BREAKAWAY_OK flag 本身" |

# 第 3 章 · 状态词表与三态语义:失联不是死亡

> 这个子系统有三套正交的词表:行状态(agent 在干嘛)、进程三态(agent 还活着吗)、展示词表(UI 画什么圆点)。
> 全章围绕一条设计宣言:**"only positive proof earns `exited`"**。引用为仓库相对路径。

---

## 3.0 三套词表总览

| 词表 | 取值 | 定义处 | 回答的问题 |
|---|---|---|---|
| **行状态**(hook 语义) | `working / blocked / waiting / done` | `src/shared/agent-status-types.ts:51` | agent 自报在干嘛 |
| **派生态**(renderer 推导) | `idle / unverifiable` | `src/renderer/src/lib/agent-row-decay-state.ts:7` | 证据过期后还能说什么 |
| **进程三态**(存在性) | `live / unverifiable / exited` | `src/shared/agent-process-presence.ts:21` | 进程还活着吗 |
| **展示词表**(UI) | 11 种 `AgentDotState` | `src/renderer/src/components/AgentStateDot.tsx:22-47` | 圆点画成什么样 |

关键区分:**行状态是 agent 的"自述",进程三态是 Orca 的"查证"**。agent 说自己 `working` 但进程已经死了——行状态停留在最后的自述,进程三态由探针独立判定。两者不互相覆盖。

## 3.1 行状态:`working / blocked / waiting / done`

```ts
export const AGENT_STATUS_STATES = ['working', 'blocked', 'waiting', 'done'] as const
// src/shared/agent-status-types.ts:51
```

- `working`:agent 在干活(PreToolUse 等事件驱动);
- `blocked`:卡在权限确认(permission prompt);
- `waiting`:在等用户回答(AskUserQuestion、Notification);
- `done`:agent 自报完成。

注意:**`done` 是自述,不是法医结论**。agent 进程崩溃时永远没机会说 `done`——这正是进程三态存在的理由。

### worktree 级聚合

一个 worktree 可能挂多个 pane,聚合优先级(`src/main/runtime/runtime-worktree-status-projection.ts:14-20`):

```
permission > working > done > active > inactive
```

**需要人处理的最优先**——blocked/permission 永远压过 working,任何一个 pane 等人,整个 worktree 就显示等人。

## 3.2 进程三态:`live / unverifiable / exited`

词表只有三个值,**刻意没有同义词**(`src/shared/agent-process-presence.ts:21`):

```ts
export type AgentProcessVerdict = 'live' | 'unverifiable' | 'exited'
```

设计宣言(`src/main/daemon/daemon-liveness-report.ts:2-7`):

> "Vocabulary per the SSH execution boundary: live / unverifiable / exited, and **only positive proof earns `exited`**."

### 探针怎么判(`src/shared/agent-process-presence-probe.ts`)

| 平台 | 证据 | 判定 |
|---|---|---|
| Linux | 读 `/proc/<pid>/stat` 失败(ESRCH/ENOENT) | **exited**(:24-26) |
| Linux | boot_id/startTime 不可解析 | unverifiable(:34-36) |
| Linux | 可读 | live(:37-42,携带 startTime/zombie/stopped) |
| macOS | `ps` 成功 / `kill(pid,0)` ESRCH | live / exited(:64-70) |
| Windows | — | unverifiable(:75-76,"no Windows hook captures an identity yet") |
| 任何 | 探针抛异常 | unverifiable(:72-74) |

注意 Windows 行:**能力不足的地方宁可永远 unverifiable,也不假装能判**。这是 fail-closed 的破坏语义在"读"方向的镜像——判死的权力必须建立在真实证据上。

### `probeAgentProcessPresence` 的两条 PID 复用防护(:79-98)

```ts
if (observed.zombie || observed.startTime !== identity.startTime) {
  return 'exited'   // :92-94
}
// Why: a suspended (Ctrl-Z) agent still exists but is not running in its terminal.
return observed.stopped ? 'unverifiable' : 'live'   // :96-97
```

- **startTime 漂移 = PID 被复用** → 原来的 agent 确实死了,exited;
- **zombie** → 死了但没被 reapa,exited;
- **Ctrl-Z 挂起** → 进程在但终端里没在跑,unverifiable——判 live 和 exited 都不对,词表逼出了正确答案。

## 3.3 "失联不是死亡":引文集

这条原则散布在 main、renderer、CLI 三层,措辞高度一致——它不是约定俗成,是被反复刻进代码的制度:

**renderer**(`agent-row-decay-state.ts:14-22`):

> "Silence is not evidence (docs/reference/ssh-execution-boundary.md), so the destination splits on the liveness Orca actually holds: a pane whose PTY is still in the live-PTY map only lost its reporting stream (`unverifiable`), while a pane with no PTY has nothing running behind it (`idle`). **Neither ever claims the agent finished.**"

**UI 圆点**(`AgentStateDot.tsx:33-37`):

> "the pane still has a live PTY but its reporting stream has gone quiet past the staleness window... never rendered as 'done' or 'working' — **it asserts nothing about the agent, only about what Orca last heard**."

unverifiable 的圆点不断言 agent 的任何事,只陈述"Orca 最后听到什么"——这是认识论上的诚实。

**main 扫尾**(`restored-status-dead-terminal-sweep.ts:42`):

> "a probe that throws is unverifiable, never evidence the terminal died."

**SSH 镜像**(`host-mirrored-pane-liveness.ts:44-52`):

> "An empty local handle map is therefore 'unverifiable', never 'exited' — the incident's replacement `codex resume` forked a session the host still held."

注释里直接引用了一次事故:替代进程 `codex resume` 把 session fork 走了,而主机还持有原 session——空句柄表只是"我还没拿到",不是"那边没有了"(#19735)。

**休眠面板**(`sleeping-agent-pane-ownership.ts:196-198`):

> "disconnect clears ptyIdsByTabId while the remote process keeps running, so a leaf bound to an unreachable SSH target is `unverifiable`, not dead."

断连清的是本地映射,不是远端进程。

**CLI**(`src/cli/worktree-ps-terminal-verdict.ts:8`):

> "`none`... Never `exited`, which needs proof of an exit"

CLI 的三态是 `live / unverifiable / none`——**连 `exited` 这个词都不给 CLI 用**,因为 CLI 拿不到进程级证据,从词表上杜绝误报。

## 3.4 陈旧窗口:30 分钟与租约续期

```ts
export const AGENT_STATUS_STALE_AFTER_MS = 30 * 60 * 1000
// src/shared/agent-status-freshness.ts:7
```

**没有周期心跳**——系统是纯事件驱动 + 新鲜度租约:

- 每个 hook 事件是一次"证据",刷新行的 `updatedAt`;
- **重复证据也续租**:"Accepted duplicate evidence renews leases without becoming a semantic row mutation"(`server-listeners.ts:117-118`)——内容相同的 hook 不产生行 mutation(不触发订阅重放),但刷新新鲜度;
- 30 分钟无证据 → stale → renderer 把 `working` 衰减为 `idle`(无 PTY)或 `unverifiable`(有 PTY)。

### 时钟规则:authority 钟 vs replica 钟

多台主机参与时,"多久没听到"该用谁的钟?`agent-status-freshness.ts:10-27` 给出完整论证:

> "A relay reconnect replays a cached row and must restamp `updatedAt`... A row mirrored from another host carries the host's stamps, so subtracting them from this machine's `now` is off by the two clocks' skew... A mirrored row therefore carries this replica's own receipt time and decays against that."

规则:**衰减永远在读者的钟上量**。镜像行带 replica 自己的接收时刻(`mirroredEvidenceReceivedAt`),本地观察行用 authority 的观察时刻(`evidenceObservedAt ?? updatedAt`)。relay 重连重放行时必须重新盖章,否则每次重连都把过期期限顺延一个窗口。

完整的衰减规则集中在 `src/shared/agent-status-observation.ts` 的 "THE DECAY RULE" 注释,其存在理由(:1-8,STA-4293):

> "An AgentStatusEntry today cannot say who observed it, on whose clock..." 

observation facet(provenance)就是为了回答"谁、在哪台钟上观察到的"(教训来自 #14657/#14626)。

## 3.5 展示词表:11 种圆点状态

`AgentDotState`(`AgentStateDot.tsx:22-47`):`working / monitoring / blocked / waiting / interrupted / failed / done / idle / unverifiable / unconfirmed / permission`——每个取值都有 Why 注释。它比行状态丰富,因为 UI 要表达**行状态 × 新鲜度 × 进程三态**的组合:

- `unverifiable`:有 PTY 但报告流静默(§3.3 引文);
- `idle`:stale 且无 live PTY;
- `unconfirmed`:冷启动恢复的行,证据先于进程边界,不适用"多久没听到"的语义(`agent-row-decay-state.ts` 对 `restoredUnconfirmed` 的豁免)。

为什么展示词表集中在共享组件:`agent-row-dot-state.ts:11-42` 的注释——"One copy so the sidebar card, the dashboard row and the notes send menu cannot drift on a new member"(详见第 6 章)。

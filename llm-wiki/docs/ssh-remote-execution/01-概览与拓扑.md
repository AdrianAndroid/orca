# 第 1 章 · 概览与拓扑

> Orca SSH / 远程执行边界总览:远端主机上跑什么、桌面怎么够到它、为什么"失联"是这个子系统的核心词。
> 核心命题一句话:**执行主机拥有触碰执行的一切;失联永远不是进程死亡的证据**。
> 本系列共 7 章,本章是地图。引用为仓库相对路径。

---

## 1.1 先正名:代码里有三个 "relay"

读这套代码最大的陷阱是 "relay" 一词三义。先立表:

| 名称 | 位置 | 角色 | 状态 |
|---|---|---|---|
| **SSH relay(relay.js)** | 远端 `~/.orca-remote/`,`relay.js --detached` | ≤1.4.224 时代的远端 PTY 租约托管 | **已退役**,只维护普查/分类/接管(legacy bridge) |
| **orcad(managed Orca server)** | 远端版本化安装 `orcad-<version>/` | 现行执行主机:完整 Orca runtime | **现役**,每次连接按需部署/迁移/更新 |
| **云 relay(@orca-cloud/relay)** | `cloud/apps/relay`(Hono + Postgres) | mobile↔desktop 配对 rendezvous / E2EE 中转 | 现役,**与 SSH 无关** |

退役的判词写在 `src/main/ssh/relay-install-artifacts.ts:1-5`:

> "Orca no longer builds or deploys the relay; the host census reads these names to classify the directories and daemons older versions left behind."

但 relay 的**解码端、终端普查、legacy bridge 仍在维护**(日落日期 2027-01-15,`src/main/ssh/legacy-relay-bridge/README.md:3`)——它是"活着的遗产",不是历史文档。本系列第 4、6 章都会回到它。

## 1.2 SSH 边界总图

```
桌面 Orca(Electron main + renderer)
  │  内置 ssh2 或 system OpenSSH(双传输,第 3 章)
  ▼
SSH 连接(SshConnection,每 target 一条,连接池管理)
  ├─ exec / SFTP 通道 ──── 部署、普查、锁、文件传输(第 6 章)
  ├─ TCP 本地转发(ssh2 forwardOut 或 ssh -L)── 首选
  │    或被拒时 stdio bridge(每 socket 一条 exec 通道跑桥脚本)
  ▼
远端 orcad(绑 loopback)⇆ 隧道 ⇒ 桌面注册为 runtime:<env> 环境
  │
  └─ renderer 经 paired-runtime WebSocket + E2EE 握手跑 runtime RPC
     (与连接本地 `orca serve` / LAN server 完全同一条协议路径)
```

两个传输的抉择点(`src/main/ssh/orcad-managed-tunnel-transport.ts:1-4`):

> "The managed tunnel's transport choice, made each time a tunnel starts: **the SSH local forward wherever the host allows it, and the stdio bridge where its sshd refuses forwarding**."

stdio bridge 的关键性质是对上层**不可区分**(`src/main/ssh/orcad-stdio-bridge-provider.ts:1-8`):

> "Nothing above the tunnel can tell the two apart... a lost transport never reads as a dead server."

断连语义不因传输而异——这是"失联 ≠ 死亡"能成立的前提(第 4 章)。

**最关键的一句**:SSH 只是"自动部署 server + 自动打隧道"。隧道建立后,renderer 与远端 orcad 之间走的是**与 LAN 配对、`orca serve`、mobile 完全相同的 runtime RPC 协议**(第 5 章)——SSH 没有私有 RPC 面。

## 1.3 每次连接的第一件事:决定 host 跑什么 server

`src/main/ssh/ssh-host-server-on-connect.ts:1-13` 的头注释是全子系统最好的架构摘要:

> "Which server an SSH host runs, decided once per connect before any relay is started.
> Every host runs managed orcad: **an empty host deploys it, a host with Orca state converts through the journaled migration, and a converted host connects through its tunnel**, updating first when it runs an older build and its terminals allow. A host whose relay terminals are live, **or can't be proven exited**, keeps the relay this session and converts on a later connect."

四种处境四条路:空 host 部署、旧状态 host 走日记化迁移、已转换 host 走隧道(旧版先更新)、**relay 终端还活着或无法证明已退出的 host 本会话保留 relay**。最后一条的注释(:217-224)是系列主题的第一次亮相:

> "Why unverifiable too: **loss of contact is never evidence that a relay terminal exited.**"

orcad 启动器加载前先校验 server 包 sha256(`src/main/orcad/launcher.ts:17-30`)——远端字节是"半可信"的(上传过,但机器不归你管),加载前必须验身。

## 1.4 术语表

| 术语 | 含义 |
|---|---|
| **target** | 一个 SSH 目的地(用户配置的 host) |
| **SshConnection / mux** | 到 target 的一条连接与其上的通道多路复用器 |
| **orcad** | managed Orca server,远端的完整 Orca runtime |
| **tunnel** | 桌面 loopback ↔ 远端 orcad 的转发通道(forward 或 stdio bridge) |
| **`runtime:<env>`** | 远端 server 在桌面注册成的环境 ID,renderer 寻址用它 |
| **ExecutionHostId** | 执行主机标识:`local` / `ssh:<target>` / `runtime:<env>`(第 2 章) |
| **fence / journal** | 激活围栏与迁移日记:中断可恢复到恰好一个槽位 |
| **census** | 对 host 上 relay/orcad 终端的普查,部署决策的事实基础 |
| **legacy bridge** | relay 时代终端的接管层,让旧 pane 继续可显示 |
| **unverifiable** | 三态判定之一:联系不上,无法证明,**不是**"没有" |

## 1.6 这个子系统最重要的设计宣言

`src/shared/pty-liveness-verdict.ts:1-13`,全子系统的宪法级注释:

> "`exited` requires positive evidence of absence from the owning host. Losing contact with that host — an unregistered SSH provider, a dropped relay, an inventory that only enumerates registered providers — is **`unverifiable`, never a death certificate and never a successful stop**."

判定词表 `live / unverifiable / exited` **没有同义词**。第 4 章整章是这一条在断连、重试、部署、删除各场景的展开;agent 状态域的同款语义见 [agent 系列第 3 章](../agent-lifecycle/03-状态词表与三态语义.md)。

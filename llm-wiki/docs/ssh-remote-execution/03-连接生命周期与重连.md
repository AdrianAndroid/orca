# 第 3 章 · 连接生命周期与重连

> 一条 SSH 连接的一生:池化复用、双传输选择、断线后的重连阶梯、以及"重连之后凭什么相信旧操作不算数"。
> 引用为仓库相对路径。

---

## 3.1 连接池:复用、拒拨、去重

`SshConnectionManager`(`src/main/ssh/ssh-connection-manager.ts`)每 target 一条连接。四条池规则,每条都有 Why:

**复用优先**(:40-44):已连接实例直接复用。

**凭证被拒 = 拒绝一切后台重拨**(:43-46):

> "Why: background dials (managed tunnel, host status, census) would retry a cancelled sign-in every few seconds; refuse them as an auth failure, without touching the network."

用户取消了登录,后台拨号器却每几秒弹一次密码框——这是对用户决定的违抗。拒拨不触网,直接抛凭证错误。

**retainedSignIns**(:16-19):池替换/关闭的连接在断开时会清登录态;没有这个保留机制,"every background redial after a drop prompts a password host again"。显式 disconnect 才忘记。

**attempt symbol**(:21-24,:95-99):每次连接尝试发一个唯一符号,被取消的连接的迟到回调拿旧符号清状态时会发现对不上——**迟到的回调不能清掉替代者的状态**(同类防护:`ssh-connection.ts:1359` "a late ready must not resurrect a torn-down client"、:1427 "guard on identity so a late event from the old client can't null out a successful reconnect")。

另注意 :71-73:"a failed startup can still hold sockets, so it is disconnected, not just forgotten"——失败启动要显式断开,不是忘掉。

## 3.2 双传输:内置 ssh2 为主,system OpenSSH 兜底

`SshConnection`(`src/main/ssh/ssh-connection.ts`,1608 行;文件头为何保留单文件的 Why 在 :1)。默认内置 ssh2,四类场景回退系统 OpenSSH:

| 场景 | 行号 | 原因 |
|---|---|---|
| GSSAPI/Kerberos | :603 | "ssh2 lacks gssapi-with-mic" |
| macOS 网络策略 | :677 | 系统 ssh 才走系统 VPN/代理栈 |
| MaxAuthTries | :742 | ssh2 的认证尝试节奏易触顶 |
| FIDO2/安全密钥 | :772 | 需要系统 ssh 的硬件交互 |

ProxyCommand/Jump 用子进程管道注入 ssh2(:623)——用户的 jump host 配置照常生效。

两个连接级细节:TCP_NODELAY(:1374,避免 ~40ms delayed-ACK 拖住交互);服务端 `LoginGraceTime` 只影响握手,不掉已建立的会话(:1380)。

## 3.3 权威纪元:fencing 三代

重连之后,旧世界发出的操作凭什么不算数?三层纪元:

**① 连接代际**(`src/main/ssh/ssh-connection-generation.ts:12-16`):

> "a removed target's id can come back (runtime-owned VM targets derive it from the runtime id); its replacement must start above every generation the prior incarnation handed out, or **a delayed mutation from the old VM passes the stale-host fence**. One scope-wide floor keeps that O(1)."

target id 会复生,所以有一个 scope 级的 `forgottenGenerationFloor`——新化身的代际从旧化身的最高水位之上开始,迟到的旧操作永远过不了栅栏。

**② provider 权威**(`src/main/ssh/ssh-provider-authority.ts`):每 target 一个 `DirectSshAuthority{targetId, providerEpoch, connectionGeneration}`;`rotateSshProviderAuthority`(:119-136)轮换时**中止旧权威的所有在途请求**。:124 的精细之处:"a recreated target skips ahead of its forgotten floor without rolling the scope; only a scope roll revokes every target"——重建单个 target 只动它自己的地板,不株连全 scope。

**③ mux 内的 tick gap 检测**(`ssh-channel-multiplexer.ts:60-63`),判"睡"不判"死":

> "Why: a tick gap far beyond the interval means the process was paused (system sleep, App Nap timer throttling) — **not that the link is dead (#7773)**."

## 3.4 重连阶梯:退避表与 flap 上限

退避表(`src/main/ssh/ssh-connection-utils.ts:39`):

```ts
export const RECONNECT_BACKOFF_MS = [1000, 2000, 5000, 5000, 10000, 10000, 10000, 30000, 30000]
```

- **健康 60s 重置**:连接撑过 `STABLE_CONNECTION_MS = 60_000`(`ssh-reconnect-ladder.ts:4-5`)视为健康,下次掉线从阶梯头重来;且 "one reset per connection, never a rolling reset mid-outage"(:39)。
- **flap 延迟上限**(:9-20)——全文件最精妙的一段:

> "Why: a flap leaves the remote relay in grace, and the shortest grace a target can configure is `MIN_SSH_RELAY_GRACE_PERIOD_SECONDS`. Retrying later than this cap would let even a full-length handshake plus relay/mux re-establishment finish after grace expires, **so the relay would shut down and take every remote PTY with it**. Raising the backoff past this bound changes nothing."

flap(连上又秒断)时远端 relay 正在烧它的宽限期(最短 60s,`src/shared/ssh-types.ts:6`)。重试太晚,握手+重建完成时 grace 已尽,relay 带着全部远端 PTY 自杀。所以 flap 的重试间隔被钉死在预算内——**指数退避在这里是错的行为**,`FLAP_DELAY_CAP_MS` 是从宽限期倒算出来的。反方向(:50-51):"a dead host keeps the full table because nothing over there is waiting for us"——真死的主机没在等谁,正常退避。

- **双计数器**(:26-31):`delayIndex` 管退避节奏(每次调度重试都前进),`consecutiveFailedAttempts` 只管握手失败——"'reconnection-failed' stays reachable exactly after RECONNECT_BACKOFF_MS.length failed handshakes — **never after flaps**"。flap 不是失败,不该把"重连失败"状态吵出来。

## 3.5 睡眠与唤醒

- **被动**:mux 的 tick gap 检测(§3.3)区分"进程被暂停"与"链路死了";
- **主动**:唤醒后立即拆旧 socket 重连(`ssh-connection.ts:890`):

> "Why: OS sleep/wake can leave ssh2 thinking a dead TCP socket is still connected; tear down and reconnect so the relay can reattach remote PTYs."

- **入口**:`src/main/ipc/ssh-host-sleep-reconnect.ts`(powerMonitor resume 触发);
- 连接广播 `reconnectAttempt=0` 触发 relay 重建(:1475)。
